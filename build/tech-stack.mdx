| Layer | Technology | What it does |
| --- | --- | --- |
| Contracts | Solidity on HyperEVM, tested with Foundry | Builder registry, per-trader vault clones, vault factory, timelocked market whitelist |
| Trading venue | HyperCore | Perps, HIP-3 markets and HIP-4 outcome markets |
| Contract to venue | CoreWriter actions and read precompiles | Vaults send orders and read positions, balances and mark prices |
| Services | Node.js 22 with TypeScript | Indexer (mirror and daily metrics) and keeper (reconcile and fast-mode watch) |
| Database | Supabase (Postgres) with row-level security | Mirror of on-chain state, Arena seasons, scores and points ledger |
| App | Next.js | Leaderboard, vault dashboard, builder tools |
| Landing page | Vite and React | agentscircle.network |
| Docs | Mintlify | This site |

## Why this stack

- **HyperEVM gives programmable custody.** A contract can own a HyperCore account, so every vault is its own account owned by its trader.
- **HyperCore gives the markets.** One engine for perps, equities, commodities and outcome markets.
- **Plain Node services.** Node 22 runs the TypeScript directly, with no build step to drift from what runs in production.
